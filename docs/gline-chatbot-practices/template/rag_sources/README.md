# rag_sources/ — 代表原稿の置き場

このディレクトリに代表の書籍・インタビュー記事・発言録などのテキストを置くと、
ペルソナ自動学習パイプラインが起動し、採用チャットボットのペルソナ改訂案を自動生成します。

---

## ファイル名規則

ファイル名が RAG の `source` タグになります。一目でわかる名前を付けてください。

```
YYYYMMDD_コンテンツ種別_タイトル略称.txt

例:
  20260101_書籍_経営の本質.txt
  20260315_インタビュー_日経ビジネス.txt
  20260401_社内講話_全社朝礼.md
```

## 推奨ファイル形式

| 形式 | 拡張子 | 備考 |
|------|--------|------|
| テキスト | `.txt` | 推奨。UTF-8 で保存。 |
| Markdown | `.md` | 見出し・箇条書き付きの原稿に適しています。 |

> PDF・Word・Excel は自動処理されません。テキストに変換してから置いてください。

## 文字起こし時の注意点

1. **話し言葉のまま残す** — 代表の口癖・語尾・言い回しが重要な学習素材です。
   「えー」「あのー」などのフィラーは削除しても構いませんが、言い回し自体は変えないでください。
2. **改行位置** — 段落ごとに空行（2 行改行）を入れてください。パイプラインが段落単位でチャンク分割します。
3. **発言者の明示** — 対談・インタビュー形式の場合は `【代表】:` のように発言者を明記してください。
   パイプラインは代表発言性が高いチャンクを優先的に RAG インデックスに登録します。
4. **個人情報の除去** — 第三者の電話番号・住所・メールアドレスは事前に削除してください。

## 1 ファイルあたりの文字数目安

| コンテンツ種別 | 目安 |
|----------------|------|
| 短いコラム・SNS投稿まとめ | 〜5,000 文字 |
| インタビュー記事 | 5,000〜30,000 文字 |
| 書籍・原稿（章単位） | 30,000〜100,000 文字 |

> Gemini 2.5 Pro の入力上限（約 1,500,000 文字）を超える場合、パイプラインが自動分割して処理します。
> ただし 1 ファイルが大きすぎると処理時間が長くなるため、章・セクション単位でファイルを分けることを推奨します。

## パイプラインのトリガー

このディレクトリに変更を push すると自動的に以下が実行されます：

1. `scripts/analyze-persona.mts` が起動
2. Gemini 2.5 Pro が原稿を分析し `tmp/persona-analysis.json` を生成
3. 既存 `prompts/sanbo-persona.md` との差分を `tmp/persona-diff.md` に出力
4. 差分がある場合、`prompts/sanbo-persona.md` の改訂案 PR が自動作成されます

また、毎週日曜日 09:00 JST にも定期実行されます。

## 必要な環境変数（GitHub Secrets）

| 変数名 | 用途 |
|--------|------|
| `GEMINI_API_KEY` | Gemini 2.5 Pro API 認証 |
| `DATABASE_URL` | RAG チャンクの再構築（PostgreSQL） |
